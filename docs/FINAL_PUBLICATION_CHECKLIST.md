# Continental — финальная публикация

**PRIVATE сохраняется до явного одобрения пользователя. Автоматически менять видимость запрещено.** Разработка, commits и обычные pushes в существующий private remote разрешены. Ссылку на официальную платформу организаторов отправляет лично пользователь; агент ничего не отправляет от его имени.

## До запроса одобрения

- [ ] Получены настоящий PROD group_id и подтверждённое время freeze с часовым поясом; новые официальные указания имеют приоритет. При изменении срока/требований пользователь немедленно уведомлён.
- [ ] Импортированы ровно10 настоящих уникальных PROD ID; право обработки проверено. Неизвестные и реальные записи не объявлены синтетическими ради обхода запрета.
- [ ] Сохранён официальный C1–C8 и настоящая provenance; результаты ошибок не заменены выдуманными баллами, manual_demo или вторым AI-мнением.
- [ ] Оба файла существуют и отслеживаются Git: `results/dev/results.json` —65 исходных ID; `results/prod/results.json` —10 настоящих ID. Пригодные записи содержат ровно8 критериев, без C9, с правильными типами, N/A,1-based evidence и пересчитанным итогом.
- [ ] Оба JSON прошли строгий validator по исходным данным. Успехи и ошибки подсчитаны отдельно. До получения PROD фиктивный файл не создаётся.
- [ ] Сборка, применимые тесты, typecheck и security-проверки пройдены; в последний час изменения кода ограничены необходимыми исправлениями сдачи.
- [ ] Проверены публичные файлы, frontend bundle, relevant Git history и все remote refs. Нет ключей/credentials, signed URLs, реальных транскриптов/аудио, SQLite, частных отчётов/пакетов и приватной разметки. Проверка шаблонов и известных значений имеет ограничения и не является абсолютной гарантией отсутствия любых преобразованных данных.
- [ ] Обычный commit и push завершены; локальный HEAD совпадает с `origin/main`. Оба удалённых JSON скачаны с авторизацией из этого точного commit, их bytes совпали с Git blobs и строгий validator пройден. Это ещё не официальная сдача.

## Краткое одобрение пользователем

Перед решением показать: точный SHA, remote/ветку, DEV/PROD ok/error counts, результат security-аудита и оставшееся время. Пользователь явно разрешает изменить именно `arysbey/freedom-cqa-continental` с PRIVATE на PUBLIC. Разрешение доступа к GitHub, private push или прежнее историческое одобрение не заменяют эту команду.

Если пользователь хочет опубликовать репозиторий раньше получения PROD, указать, что PROD-проверки ещё не завершены. Его последующий настоящий JSON проходит тот же аудит, validation, push и анонимную проверку до freeze.

## После явного одобрения, до freeze

- [ ] Переключена только видимость согласованного репозитория; исходники, данные и Git history не переписываются.
- [ ] GitHub metadata без авторизации показывает `private=false`, remote SHA совпадает с утверждённым commit.
- [ ] Без токена, cookies и Authorization получены HTTP200 для репозитория и **обоих** путей результатов из финального SHA; ответы — настоящие JSON, не HTML/login.
- [ ] Bytes обоих файлов совпадают с финальными Git blobs, строгий validator подтверждает DEV65/PROD10 исходных ID.
- [ ] Проверка завершена **до официального deadline**. Публикация после срока не считается своевременной сдачей.
- [ ] Пользователю переданы ссылка, SHA, counts и время проверки. **Пользователь лично** отправляет ссылку через официальную платформу и проверяет подтверждение приёма.

## Временной резерв

По сообщённому старту расчёт:8 ноября2026,11:00 выдача,12:00 freeze,UTC+05. Это не независимое подтверждение организаторов. К10:30 приоритет — release readiness; с выдачей PROD необязательные эксперименты прекращаются. При подтверждённом freeze12:00 общий model cutoff11:38 сохраняет22мин на экспорт, аудит, push, публикацию, анонимную проверку и действия пользователя. Новый полный120-секундный запрос требует запаса и перестанет стартовать примерно до11:36. Одобрение публикации не следует откладывать на последние минуты: ориентир планирования — завершить публикацию и анонимную проверку к11:50, если данные готовы; это внутренний ориентир, не официальный срок и не гарантия времени.

При отказе пользователя, недоступности GitHub, несовпадении SHA/байтов, непройденном аудите, отсутствии настоящего PROD или истечении срока: сохранить фактический статус и немедленно сообщить блокер. Не force-push, не скрывать ошибки и не объявлять сдачу завершённой по одному private push.
