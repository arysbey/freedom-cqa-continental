# Протокол проверки качества CQA

Статус: подготовка к независимой проверке. Метрик качества модели пока нет. Успешный JSON, корректные ссылки и программные тесты подтверждают технический контракт, но не правильность интерпретации диалога.

## Что уже подготовлено

Локально независимо от результатов оценивающей модели просмотрены разрешённые синтетические DEV-чаты `p1-kz-001` и `p1-en-001`. Предварительные ответы, точные цитаты, ID реплик, проверенные диапазоны и спорные места сохранены только в игнорируемом `private/reports/proposed-labels.json`.

Это предложения кодирующего агента, **не человеческая разметка, не gold set и не измерение точности**. Они не должны автоматически утверждаться той же моделью, которая оценивает чаты. Проверяющему нужно принять или исправить каждое предложение до включения примера в эталон.

## Безопасная выборка

Для первого ограниченного прогона достаточно одного разрешённого синтетического чата на RU, KZ и EN. Такой прогон проверяет доступность и способность соблюдать контракт на трёх языках; он не представляет весь DEV.

Для следующей проверки подготовить 12 синтетических чатов, по четыре на каждый язык. Выборку разделить до настройки промпта на шесть рабочих примеров и шесть отложенных. Распределение сохранить в частном манифесте вместе с версиями разговоров. При недостаточном покрытии конкретной ситуации добавить отдельный придуманный безопасный пример с явно подтверждённым происхождением; он не становится DEV и не должен обходить действующую политику разрешения данных.

Среди выбранных примеров должны присутствовать:

- приветствие бота без приветствия оператора;
- необходимая проверка личности, включая позднюю и отсутствующую;
- несколько существенных вопросов и частичная консультация;
- разрешённый N/A, спорный N/A и пропущенное обязательное действие;
- прерывание клиентом и завершение оператором;
- предложение частной платной услуги, оскорбление либо раскрытие данных;
- системные сообщения и одинаковые timestamps;
- материально изменённый или новый критерий.

Пять реальных звонков, их производные материалы, аудио и подписанные ссылки в эту внешнюю проверку не включаются. Новые группы с неизвестным разрешением остаются заблокированными. Присутствие записи в выборке не заменяет серверную проверку допустимости.

## Человеческий эталон

Каждый пример размечается до просмотра результата оценивающей модели. Предпочтительны два независимых человека, включая специалиста, понимающего соответствующий язык и правила поддержки. Если доступен один проверяющий, это явно фиксируется как ограничение, а не называется независимым двойным контролем.

По каждому из восьми критериев сохранить:

1. Версии разговора и чек-листа, ID критерия, ответ из разрешённой шкалы.
2. Причину применимости или точное условие N/A.
3. Обоснование, точные цитаты с ID реплик, диапазон для пропущенного действия.
4. Уверенность и нерешённый вопрос, если без предметных знаний вывод недоказуем.
5. Имя либо локальный ID проверяющего, дату и итог разрешения разногласий.

Не засчитывать боту действия человека. Не подменять отсутствие обязательной проверки личности значением N/A. При проверке C7 требуются прощание **и** итог либо предложение дальнейшей помощи. Обычное «пожалуйста» не является автоматически итогом. Слова вежливости сами по себе также не доказывают правильность консультации.

У C2 отдельно согласовать, что означает «данных хватало с самого начала», если нужные сведения появились при работе бота до подключения человека. Сохранить принятую трактовку и не менять её после просмотра спорного ответа модели. Для C4 нельзя подтверждать внутреннюю политику компании только уверенностью оператора; при отсутствии проверяемого предметного источника оставить этот аспект нерешённым и передать человеку.

Предварительные машинные предложения могут помогать навигации, но не заменяют запись о человеческом утверждении. Нерешённые позиции не включать в знаменатель метрики согласия; их количество показывать отдельно.

## Фиксация прогона

До запроса зафиксировать состав выборки, человеческие ответы, версии чек-листа, модель, параметры, версию промпта и конфигурацию минимизации. Вызовы выполнять последовательно с ограниченными повторами. Не изменять ответы или диапазоны задним числом ради прохождения сравнения.

Для каждой попытки сохранить локально результат либо явную ошибку, время, действительное число вызовов и доступный token usage. Отсутствующие показатели остаются неизвестными. Отказ квоты, таймаут, неверный JSON и непрошедшие проверку доказательства не становятся нулевым либо идеальным баллом.

## Что считать

| Проверка | Правило отчёта |
| --- | --- |
| Согласие по критериям | Число совпадений / число утверждённых человеческих ответов; отдельно для RU, KZ, EN и каждого критерия |
| N/A | Матрица применимо/N/A, ложные и пропущенные N/A, конкретные спорные случаи |
| Итоговый балл | Средняя и максимальная абсолютная ошибка против расчёта по утверждённым ответам, с числом диалогов |
| Ссылки и цитаты | Доля технически валидных ссылок и точных цитат; отдельно человеческая оценка того, подтверждает ли фрагмент вывод |
| Грубые ошибки | Количество истинных и ложных флагов, пропущенных нарушений; при отсутствии положительных примеров полнота не оценивается |
| Надёжность | Успешные, отклонённые и неуспешные попытки / все попытки; задержка и реальный usage |
| Новая семантика | Новый критерий передан модели, ответ связан с его смыслом, арифметика использует новую версию, старый результат сохранён |

Малую выборку описывать числом проверенных случаев, а не общей «точностью системы». Нельзя выводить качество казахского или английского по одному удачному чату. Время API не равно экономии рабочего времени проверяющего.

## Ограниченные улучшения

Сначала разобрать содержательные расхождения по одному: неверная роль, условие N/A, пропущенный вопрос, необоснованный флаг, неподходящее доказательство. Допускается небольшая правка инструкции или схемы. После неё повторить рабочую часть выборки, сохранить расход и причину изменения. Отложенные примеры использовать только после выбора конфигурации; результаты настройки на них не называть независимой проверкой.

Оплату либо смену политики обработки не включать автоматически. Обсуждение платного провайдера возможно только после зафиксированного существенного сбоя и отдельного разрешения пользователя.
