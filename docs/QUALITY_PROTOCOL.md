# Независимая проверка качества CQA

## Зафиксированная выборка

В локальной базе подготовлен манифест `dev-balanced12-2dccf6cc8688`: 12 разрешённых синтетических DEV-чатов, по четыре RU/KZ/EN. Шесть рабочих и шесть отложенных примеров выбраны до нового прогона. Ранее использованные для настройки p1-ru-001, p1-kz-001, p1-en-001 исключены.

Модель зафиксирована: Gemini 3.1 Flash Lite, текущая серверная конфигурация без смены провайдера или биллинга. Чек-лист: сохранённая через интерфейс версия `custom-dac7027c-19e3-4aeb-a478-5936239bd400` с девятью критериями, включая C9 и уточнения C2/C7. Манифест содержит точные версии каждого разговора и чек-листа; сравнение по чужой версии запрещено.

| Язык | Рабочие примеры | Отложенные примеры |
| --- | --- | --- |
| RU | p1-ru-003, p1-ru-025 | p1-ru-014, p1-ru-029 |
| KZ | p1-kz-005, p1-kz-015 | p1-kz-003, p1-kz-013 |
| EN | p1-en-006, p1-en-009 | p1-en-007, p1-en-015 |

Выборка покрывает действия бота и человека, N/A против пропуска обязательного действия, проверку личности до и после раскрытия сведений, частичную/ошибочную консультацию, дополнительный вопрос без ответа, неудобство клиента и эмпатию, завершение и потерю соединения, категории грубых нарушений. C9 входит в фактическую конфигурацию каждого примера. Это покрытие ситуаций в исходных текстах, не заранее назначенные правильные ответы.

Полный манифест и снимок чек-листа сохранены в игнорируемом `private/validation/dev-balanced12-2dccf6cc8688.json`. Исходные выдержки и реальные звонки в публичную документацию не включены. Сервер повторно проверяет разрешённый хеш каждого синтетического разговора.

## Человеческий эталон и слепая разметка

В разделе «Проверка качества» видны разговор и правила, но не ответы модели до фиксации человеком соответствующего решения. Ответы изначально пусты. Ранние агентные предложения из `private/reports/proposed-labels.json` не загружаются и не попадают в метрики.

Проверяющий вводит своё имя или локальный ID, самостоятельно читает текст, выбирает ответ и пишет обоснование. Для N/A указывает выполненное условие. Добавляет точную цитату с реальным ID реплики либо проверенный диапазон; для пропуска и частичного балла диапазон обязателен. Неясный пункт оставляет нерешённым: он не входит в знаменатель согласия. Внутреннюю политику компании нельзя подтверждать только уверенностью оператора; без предметных знаний такой аспект оставляется нерешённым.

Сохранение требует двух явных подтверждений: проверяющий — человек; новые решения вынесены без просмотра ответов модели. Самоподтверждение локальное и не выдаётся за независимую проверку личности. Можно сохранить часть критериев и продолжить позже. Подтверждённые слепые решения остаются неизменяемыми; новые версии могут дополнять только ранее нерешённые пункты. История сохраняется.

После частичной фиксации сервер открывает модельные ответы только по уже проверенным критериям. Ответы по нерешённым пунктам и общий балл остаются скрытыми до полной разметки. Просмотр вне этого раздела исключить организационно: приложение без регистрации не может доказать, что человек не видел ответ в другом месте.

После фиксации эталона человек отдельно оценивает, подтверждает ли цитата вывод модели, выбирает категорию расхождения и комментирует его. Это хранится отдельно от технической проверки ID и текста цитаты и не меняет исходную метку.

Агентные демонстрации ручного ввода, тестовые фикстуры, оценки звонков и апелляции не становятся автоматически gold set. Для согласия используются только записи отдельной таблицы человеческих эталонов со слепым подтверждением.

## Метрики

| Показатель | Правило |
| --- | --- |
| Согласие по критерию | Совпадения / решённые человеческие ответы; точная версия чек-листа |
| Языки и разбиение | Отдельные счётчики RU/KZ/EN и development/holdout с числом наблюдений |
| N/A | Ложный, пропущенный и верный N/A; верная применимость |
| Итог | MAE и максимальная абсолютная ошибка только полностью решённых примеров |
| Доказательства | Технические ID, точные подстроки и диапазоны; отдельно смысловая поддержка человеком |
| Грубые нарушения | TP/TN/FP/FN; без положительных человеческих примеров полнота не доказана |
| Надёжность | Все успешные/неуспешные попытки, коды ошибок, медиана/p95/максимум задержки |
| Usage | Сообщённые токены, известные вызовы; неизвестные показатели остаются неизвестными |
| Расхождения | Каждый случай с языком, критерием, двумя ответами, объяснениями и категорией |

При нуле человеческих решений согласие и ошибка балла неизмерены (`null`), а не 0% и не 100%. Корректный JSON не равен правильной интерпретации. Частичная разметка не даёт общего человеческого балла.

Сопоставляется только `live_validated` результат Gemini 3.1 Flash Lite с точными версиями. Ручной ввод, агентная демонстрация, другая модель и несовпадающая версия не участвуют. Неудачный вызов не становится нулевой либо идеальной оценкой.

## Воспроизводимый прогон

```powershell
node node_modules/tsx/dist/cli.mjs scripts/prepare-validation.ts
node node_modules/tsx/dist/cli.mjs scripts/run-validation.ts --dry-run
node node_modules/tsx/dist/cli.mjs scripts/run-validation.ts --split development
node node_modules/tsx/dist/cli.mjs scripts/run-validation.ts --split holdout
```

По умолчанию runner вызывает модель только для случаев с человеческими решениями. До человеческой работы возможен явно обозначенный технический baseline:

```powershell
node node_modules/tsx/dist/cli.mjs scripts/run-validation.ts --allow-unreviewed --split development --limit 6
node node_modules/tsx/dist/cli.mjs scripts/run-validation.ts --allow-unreviewed --case p1-en-009 --limit 1
```

Флаг не создаёт эталон и не создаёт числовую точность. Он фиксирует настоящие ответы/ошибки и метаданные. После слепой разметки сопоставление выполняется автоматически; повторный вызов не нужен при той же конфигурации. Повтор уже успешного случая требует `--rerun`.

Вызовы последовательны. Каждая попытка фиксируется сервером; серия прекращается при квоте, отсутствующем ключе, неподтверждённом Free tier или недоступной модели. Отчёт — только `private/validation/<manifest-id>-metrics.json`.

## Разбор и ограниченные улучшения

Сначала разобрать рабочие расхождения: роль, N/A, порядок идентификации, полнота ответа, эмпатия, завершение, грубое нарушение, доказательства, язык. Причину нельзя выводить только из несовпавшего числа: нужен исходный фрагмент и комментарий проверяющего.

Уточнять правила или валидацию только после конкретного сбоя. Создать новую неизменяемую версию, не переписывая исходный результат. Проверить на другом рабочем примере, затем на отложенных. Повтор на известном примере не является независимой проверкой. После просмотра holdout нельзя одновременно использовать его для настройки и заявления итоговой точности.

Платный тест или другая модель требуют измеренной причины и отдельного согласия. Недостаток человеческого эталона не является причиной покупать более дорогую модель. Реальные пять звонков, аудио и производные материалы в бесплатный API не отправляются.
