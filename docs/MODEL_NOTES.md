# Наблюдения о модели и обработке данных

Снимок от 2026-11-07. Ниже описаны фактически выполненные локальные проверки и независимый разбор кодирующим агентом. Это **не человеческий gold set, не оценка общей точности и не подтверждение готовности для реальных клиентских данных**. Транскрипты, ответы модели с цитатами, диагностические файлы и исходные записи остаются в игнорируемом `private/`.

## Содержательный разбор сохранённых оценок

Правила взяты из [версионного официального чек-листа](../src/data/official-checklist.json); сверка с предоставленным PDF описана в [аудите источников](SOURCE_AUDIT.md).

- **C7, завершение:** в первом результате Flash-Lite стоит YES, а объяснение подтверждает только прощание. Правило требует одновременно прощания и итога либо предложения дальнейшей помощи. В проверенном заключительном участке второго элемента нет. Предложение агента — NO; технически точная цитата сама по себе не подтверждает полный критерий. После уточнения формулировки повтор вернул NO.
- **C2, выявление потребности:** при первом запуске Flash-Lite поставила YES за учёт известного контекста, не показав уточнения недостающих данных. Достаточные сведения были доступны до первой реплики человека-оператора. Предложение агента — N/A по официальному условию достаточности исходных данных; именно такой ответ получен в исходной оценке 3.8. Человек должен утвердить трактовку начала обслуживания при передаче от бота. После уточнения формулировки повтор вернул N/A.
- **C5, эмпатия:** исходное YES у 3.8 обоснованно по агентной проверке: оператор предложил путь, учитывающий описанное неудобство. Однако объяснение упускает само неудобство, а выбранное доказательство подтверждает только вежливость. Для содержательно полного обоснования нужны также запрос клиента и адаптированный ответ оператора. Сохранённый результат не переписывался.
- **C9, новое правило:** Flash-Lite распознала новую семантику и вернула NO с диапазоном проверки. Это подтверждает один фактический сценарий динамического чек-листа, но не доказывает правильную интерпретацию всех произвольных новых критериев.

Предложенный агентом результат для девятикритериального чек-листа составляет 80,00: 60 / 75 × 100. Он совпал с последним настоящим ответом модели: C1=YES, C2=N/A, C3=N/A, C4=20, C5=YES, C6=10, C7=NO, C8=NO, C9=NO. Совпадение после настройки на этом примере не превращает его в утверждённый человеческий эталон.

Результаты показывают различие между валидными ссылками и правильной интерпретацией. Формулировки C2 и C7 уточнены в новой версии через UI, без специальных ветвей по ID критерия в коде. Повтор на том же примере является настройкой на известном случае; он не заменяет отложенную выборку и [человеческую проверку](QUALITY_PROTOCOL.md).

## Согласование контракта N/A и повторная проверка браузером

Последний ответ первоначально отклонён локальным валидатором, потому что у C3=N/A отсутствовал `checkedRange`, хотя присутствовали точная исходная цитата и объяснение допустимости N/A. Официальное правило требует обоснованного N/A и подтверждающего контекста; обязательный диапазон относится к отсутствующим действиям. Контракт согласован с этим различием: для N/A нужны непустое обоснование и точное подтверждающее доказательство **либо** проверенный диапазон. Для отрицательных ответов, пропусков и частичных числовых оценок диапазон остаётся обязательным. Никаких выдуманных диапазонов в ответ модели не добавлялось.

Тот же сохранённый ответ повторно прошёл проверку с исходными ответами, цитатами, usage и задержкой, без дополнительного AI-запроса. После этого браузерный сценарий с настоящим backend и без сетевых имитаций проверил историю последней оценки: апелляция и решение по C9 изменили NO на YES, итог пересчитался с 80,00 до 93,33; второе решение вернуло NO и итог 80,00. Для этой оценки сохранены две апелляции и два решения. Официальная исходная оценка 92,31 осталась неизменной. Ошибок браузера в этом прогоне не зафиксировано. Это проверка работы интерфейса, истории и арифметики; демонстрационное решение по апелляции не является новым утверждением о качестве оператора.

## Бесплатный доступ и границы данных

Условия бесплатного Gemini API допускают использование входных данных и ответов для улучшения продуктов и человеческую проверку. Поэтому приложение разрешает внешнюю обработку только явно допущенных синтетических записей. Реальные звонки, транскрипты звонков, аудио, подписанные ссылки и производные материалы заблокированы для бесплатного провайдера. Неизвестная классификация также блокируется. [Условия Gemini API](https://ai.google.dev/gemini-api/terms?authuser=00).

Перед запросом сервер удаляет из представления для модели исходный идентификатор разговора и аудиоданные, маскирует URL, контактные данные и длинные числовые идентификаторы. Модель получает минимизированные реплики и текущие правила. Цитаты сначала проверяются по этому представлению, затем восстанавливаются локально и повторно сравниваются с неизменным оригиналом. Минимизация не является основанием отправлять запрещённые реальные записи.

Ключ хранится только на сервере в игнорируемом окружении. Пользователь подтвердил Free-проект без платного биллинга; биллинг не включался. Наличие модели в каталоге и её ID не доказывают бесплатный тариф конкретного проекта или успешность генерации. Фактические квоты нужно проверять в AI Studio; они применяются к проекту и могут различаться. [Тарифы](https://ai.google.dev/gemini-api/docs/pricing?authuser=2), [квоты](https://ai.google.dev/gemini-api/docs/rate-limits?hl=en), [настройка ключей](https://ai.google.dev/gemini-api/docs/api-key?authuser=00).

## Возможная ограниченная оптимизация

Для `generateContent` у Gemini 3.8 по умолчанию используется MEDIUM; режим LOW поддерживается, MINIMAL возвращает ошибку. У 2.5 применяют `thinkingBudget`, например 1024, вместо `thinkingLevel`. Эти параметры нельзя смешивать. Изменение режима рассуждений пока не является проверенным улучшением качества или задержки этого продукта. Его следует проверять отдельным ограниченным сравнением с фиксацией конфигурации. [Официальное руководство по thinking](https://ai.google.dev/gemini-api/docs/generate-content/thinking?hl=en).

HTTP 504 означает, что сервис не завершил запрос в заданный срок. Одни эти наблюдения не позволяют установить, вызвана ли задержка рассуждениями, нагрузкой сервиса или иным фактором. Автоматического перехода на платный тариф, обхода квот и подмены ошибочного ответа имитацией нет. [Ошибки Generate Content API](https://ai.google.dev/gemini-api/docs/generate-content/api-errors?authuser=09&hl=en).
