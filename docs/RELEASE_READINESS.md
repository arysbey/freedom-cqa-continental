## Что изменилось

- Первый валидный результат фиксируется в порядке записанных прогонов. Частный JSON/CSV экспорт связывает версии, хэши и временной срез, показывает только действительно размеченные пункты.
- Автоматический повтор временного сетевого отказа ограничен одним, паузой 500 мс и общим бюджетом 120 с. Строгая проверка доказательств сохранена. Явное восстановление ограничено одним дочерним запросом; ключ запроса защищает от повторной генерации при повторе отправки.
- История показывает безопасные причины, события и фактическое число вызовов. После перезапуска незавершённый запрос отмечается прерванным, с неизвестным итогом провайдера и расходом.
- Начальный экран показывает DEV65 и официальный C1–C8. Локальная фикстура отделена фильтром; изменённые критерии доступны отдельно. Сохранённый ответ явно обозначен прошлым результатом.
- По последующему запросу пользователя открыт новый человеческий раунд текущих12 примеров. Пять прежних снимков разметки по четырём диалогам сохранены, исключены из текущего сравнения. На момент сброса все108 пунктов были нерешены; пользователь затем продолжил разметку. Записи источников, модели, чек-листов и апелляций не менялись при сбросе.

## Перед стоп-кодом

1. Заново разметить примеры человеком, разобрать C2/C7 и смысловую поддержку доказательств. Повторный раунд не восстанавливает память о ранее показанных ответах модели; учитывать это в выводах о независимости.
2. Получить официальный старт/календарный дедлайн и контрольный ID. Guide подтверждает только контроль+23ч и стоп-код+24ч, точное расписание сообщается отдельно.
3. Использовать проверенный300-секундный сценарий и сохранённые результаты текущей модели. Перед выступлением отрепетировать речь ведущего; после существенного изменения приложения повторить технический прогон. Не обещать свежую генерацию при ненадёжной сети.
4. После разрешения пользователя создать публичный репозиторий, проверить его содержимое и отправить ссылку до официального срока. Локальные ключи, подписанные ссылки, аудио, SQLite и человеческие данные в Git не включать.

Платное сравнение сейчас не обосновано: достаточной проверенной человеческой базы нет. Конкретные риски сначала проверить в текущей модели на рабочих примерах и отдельно оценить на отложенных.
