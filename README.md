# Freedom CQA · Evidence Desk

Локальная система оценки оператора: React/TypeScript, Fastify, SQLite (`node:sqlite`) и официальный `@google/genai`. Слева — диалоги и фильтры, в центре — транскрипт и доказательства, справа — критерии, баллы и пересмотр. Регистрация для демонстрации не требуется; роли не являются production-авторизацией.

## Запуск с чистой копии

Нужны Node.js 24+ и pnpm. Выполняйте команды из корня проекта:

```powershell
pnpm install --frozen-lockfile --store-dir .pnpm-store --config.enable-global-virtual-store=false --config.node-linker=hoisted --config.package-import-method=copy
if (!(Test-Path .env)) { Copy-Item .env.example .env }
# Заполните .env в локальном редакторе; существующий файл не перезаписывайте.
pnpm build
pnpm start
```

Интерфейс: [http://127.0.0.1:3001](http://127.0.0.1:3001). Сервер слушает только localhost. Свежая база автоматически получает официальный восьмикритериальный чек-лист; диалогов и оценок в ней нет. DEV, ключи, аудио и локальные результаты в исходный код не включены — их нужно импортировать отдельно.

В подготовленной рабочей папке зависимости уже установлены. Без pnpm в PATH:

```powershell
node node_modules/vite/bin/vite.js build
node node_modules/tsx/dist/cli.mjs server/index.ts
```

Для разработки: `pnpm dev` перезапускает сервер, `pnpm exec vite` запускает frontend с API proxy. `PORT` и `CQA_DB_PATH` задаются в серверном окружении.

## Ключ, модель и границы данных

1. В [Google AI Studio](https://aistudio.google.com/apikey) проверьте проект **Free tier без платного биллинга**.
2. Запишите `GEMINI_API_KEY=...` в локальный `.env`, затем задайте `GEMINI_FREE_TIER_CONFIRMED=true`. Уже заданное окружение имеет приоритет.
3. Не отправляйте ключ в чат, не вводите его командой с сохранением в history и не используйте префикс `VITE_`.
4. `pnpm models` проверяет каталог, но не подтверждает тариф, генерацию или квоту. Лимиты проверяются в AI Studio.

Текущая конфигурация — **`gemini-3.1-flash-lite`, Free, LOW thinking**. На этой фазе модель и провайдер не менялись, платный биллинг не активировался. Для их смены нужно отдельное решение пользователя. Ошибки и невалидные доказательства не подменяются оценкой 0/100 или 100/100.

Бесплатный Gemini может использовать отправленные данные для улучшения продуктов: [официальные условия](https://ai.google.dev/gemini-api/terms). Разрешены проверенные по содержимому синтетические DEV-чаты. Перед запросом маскируются URL, email, телефоны и длинные ID; цитаты восстанавливаются локально и сверяются с оригиналом.

**Реальные звонки, аудио, транскрипты и производные материалы в бесплатный Gemini не отправляются.** Неизвестные записи блокируются. Для нового синтетического чата без аудио интерфейс предусматривает явное подтверждение человеком происхождения и разрешения Free-tier обработки. Оно связано с одной неизменяемой версией; звонки этим путём разрешить нельзя. На текущем контрольном этапе таких рабочих разрешений не создавалось.

## Импорт и автоматическая оценка

Подписанную GET-ссылку храните только в `CQA_ORGANIZER_URL` серверного `.env`. Не включайте её в код, клиентский bundle, README, скриншоты и логи.

```powershell
pnpm import:dev
pnpm evaluate:first
pnpm import:dev --group CONTROL_GROUP_ID
pnpm import:dev --file 'C:\path\to\organizer-response.json'
```

В интерфейсе доступны «Импорт GET» с произвольным `group_id` и «Загрузить JSON локально». Формат — официальный envelope: `error`, `isSuccess`, `data.dataset_group_id`, `total_records`, `records`. Новая группа загружается без правки кода; импорт сам по себе не разрешает передачу данных модели.

Исходные роли, тексты, порядок и повторяющиеся timestamps сохраняются. ID сообщения зависит от версии и позиции. Повторный импорт не удаляет старые оценки. Выберите диалог и чек-лист, запустите оценку и проверьте объяснения с переходами к исходным репликам.

Для соревнования начальный фильтр — **DEV**, начальный чек-лист нового запроса — **официальный C1–C8**. Локальные тестовые группы видны только при выборе другой группы или «Все группы». Сохранённый результат показывает собственную версию правил и дату; выбранные правила нового запроса его не переписывают. Надпись «Сохранённый результат API» означает прошлый настоящий ответ, а не новый вызов.

### Ограниченное восстановление запроса

Каждый запуск имеет `requestId`: повтор отправки того же ID возвращает прежний результат или статус и не вызывает модель заново. Журнал показывает количество вызовов провайдера, события, задержку, общий бюджет и безопасный код причины. Старые записи без такой телеметрии показывают неизвестное количество вызовов.

При временном сетевом сбое, HTTP 429 или 503 допускается **не более одного автоматического повтора** с паузой 500 мс. Общий бюджет обоих вызовов — `CQA_TIMEOUT_MS` (по умолчанию 120 с); скрытые повторы SDK выключены. Таймаут, невалидный JSON и неправильные доказательства автоматически не повторяются. Проверки цитат, диапазонов и N/A сохраняются без послаблений.

Для подходящего завершённого отказа доступна отдельная кнопка однократного восстановления: новый ID связан с исходной ошибкой, версия разговора, чек-листа и модель остаются теми же. Для одного отказа нельзя создать несколько восстановлений или цепочку повторов. Квота требует ожидания; платный fallback не включается. Ошибка остаётся в истории; неизвестный расход не заменяется нулём.

Вся цепочка «первый запуск + один явный повтор» ограничена четырьмя вызовами провайдера: не более двух в каждом запуске. Историческая попытка другой модели не получает кнопку восстановления с текущей моделью.

После аварийного перезапуска ранее незавершённая попытка получает `REQUEST_INTERRUPTED`: итог провайдера и окончательный расход неизвестны. Приложение сохраняет только наблюдавшиеся события, не вызывает модель автоматически и допускает одно явное восстановление.

## Расчёт, версии и апелляции

Начальные правила: `src/data/official-checklist.json`. C1–C7 имеют вес 100 в сумме; C8 — отдельный флаг без веса. YES даёт полный вес, NO — 0; числовой вклад: `weight * answer / scaleMax`. N/A исключается из знаменателя. Итог: `100 * sum(contributions) / sum(applicableWeights)`; округление до двух знаков выполняется только в конце. При отсутствии применимых весов итог `null`. Секции используют собственные применимые веса.

Расчёт выполняется точными рациональными числами в коде. Модель предлагает ответы, но не считает итог. Для N/A нужны причина и цитата либо диапазон; для пропущенного действия и частичного балла диапазон обязателен. Цитата должна точно совпадать с источником.

«Чек-листы» позволяют добавить, изменить и удалить критерий, задать его смысл, шкалу, вес, раздел и N/A. Сохранение создаёт новую версию; старые результаты используют прежние правила.

В сохранённой AI- или ручной оценке «Заявитель» подаёт апелляцию, «Проверяющий» подтверждает или меняет ответ с причиной. Исходник, решение и пересчёт сохраняются после перезапуска. Пересмотр не вызывает модель; повтор запроса не создаёт второе решение.

## Звонки: аудио и ручная оценка

Сервер получает HTML-плеер организатора, извлекает подписанный адрес и сохраняет проверенный MP3 в `private/audio-cache/`. Браузер видит только локальный `/audio` proxy с byte ranges. Подписанные адреса браузеру не возвращаются. Для всех 5 реальных DEV-записей подтверждены декодирование, движение времени и воспроизведение в Chrome.

Переход от метки транскрипта к аудио приблизительный: он считается от первой метки; ASR-время и длительность записи могут отличаться. Точное выравнивание слов не заявляется. При недоступном источнике показывается причина; транскрипт и ручная форма остаются доступны.

Проверяющий выбирает каждый ответ, добавляет обоснование, точные цитаты и диапазоны. Черновик сохраняется локально в браузере; готовая запись — в SQLite. Для рабочей записи человек указывает себя и подтверждает собственную проверку. Это не создаёт автоматически эталон качества AI.

**«Техническая демонстрация агента»** сохраняется как `manual_demo`, отдельно от `human_entered` и `live_validated`; человеческим суждением или AI-оценкой не считается. Пять таких записей созданы для проверки формы и пересчёта; их баллы не являются экспертными оценками операторов. Для ручного контура вызовов модели — 0.

## Независимая проверка качества

Основная выборка: 12 разрешённых синтетических DEV-чатов, по 4 RU/KZ/EN; заранее разделена на 6 рабочих и 6 отложенных. Ранее использованные для настройки диалоги исключены. Смысловые проверки изменённых критериев учитываются отдельно. Проверочная конфигурация хранится как версионированные данные.

```powershell
node node_modules/tsx/dist/cli.mjs scripts/prepare-validation.ts
node node_modules/tsx/dist/cli.mjs scripts/run-validation.ts --split development
node node_modules/tsx/dist/cli.mjs scripts/run-validation.ts --split holdout
```

В «Проверке качества» человек размечает источник вслепую: результаты модели скрыты до сохранения соответствующих решений. Эталоны находятся в отдельных append-only таблицах. Нерешённые позиции исключаются из знаменателя согласия; score error считается после разрешения всех критериев с положительным весом. Нерешённый флаг C8 при этом остаётся скрытым и не включается в gross-метрики.

По умолчанию runner требует человеческую разметку и пропускает уже успешные примеры. Без подходящих эталонов он возвращает `BLOCKED` без вызовов. Явный технический baseline без эталона:

```powershell
node node_modules/tsx/dist/cli.mjs scripts/run-validation.ts --split development --limit 6 --allow-unreviewed
# Выбранные примеры без вызовов:
node node_modules/tsx/dist/cli.mjs scripts/run-validation.ts --allow-unreviewed --dry-run
```

`--manifest ID`, `--case ID`, `--limit N` ограничивают прогон; `--rerun` разрешает повтор успешных примеров. Live-прогон расходует бесплатную квоту. При **0 человеческих эталонов качество не измерено**: согласие и score error равны `null`; N/A и gross FP/FN имеют `available=false`. Нулевые счётчики означают отсутствие сравнений, а не отсутствие ошибок. Валидность ссылок и задержки учитываются отдельно от смысловой правильности. Подробности — [QUALITY_PROTOCOL](docs/QUALITY_PROTOCOL.md).

Сравнение не требует нового вызова модели. Оно выбирает **первый валидный результат в порядке записанных прогонов**, а не наиболее удачный повтор. Вкладка позволяет обновить сравнение и скачать частный JSON. Воспроизводимый read-only экспорт с хэшами источников и пятью CSV:

```powershell
node node_modules/tsx/dist/cli.mjs scripts/export-comparison.ts --manifest dev-balanced12-2dccf6cc8688
# Фиксация исторического среза (пример формата времени):
node node_modules/tsx/dist/cli.mjs scripts/export-comparison.ts --manifest dev-balanced12-2dccf6cc8688 --cutoff 2026-11-07T11:39:10.896Z
```

Экспорт записывается в `private/reports/`. Для каждой реально разрешённой позиции доступны оба ответа, объяснения, цитаты и категория расхождения; ответы по нерешённым позициям скрыты. Срез с одной отметкой из 108 не подтверждает точность модели и не оправдывает платное сравнение.

### Начать человеческую разметку заново

Подтверждённые ответы не удаляются и не исправляются на месте. Отдельный раунд выбранной проверки (`quality_review_rounds`) сохраняет прежние снимки в аудите и исключает их из текущих метрик. Разговоры, результаты Gemini, версии правил, апелляции и разбиение 6/6 остаются прежними. Исторический экспорт выбирает раунд на момент `cutoff`.

Серверный `POST /api/quality/review-rounds` принимает `{manifestId, reviewerId, requestId, expectedRoundId}`. Перед таким действием нужна резервная копия SQLite. Текущий раунд виден в dashboard; новая разметка передаёт `reviewRoundId`. Отправка старого черновика получает `REVIEW_ROUND_CHANGED`. Новый раунд не стирает память о ранее показанных ответах модели; его нельзя автоматически считать новой независимой слепой проверкой.

Черновики раздела проверки качества хранятся в памяти страницы; при смене раунда очищаются ответы, обоснования, цитаты, диапазоны, подтверждения и незавершённый запрос сохранения. Вкладка обнаруживает смену раунда; при старой версии интерфейса обновите страницу. Черновики ручных оценок звонков в localStorage имеют другой контур и сохраняются.

Эти browser-сценарии не подменяют провайдера mocks. Двойники применяются только в программных тестах; искусственный 429 не означает фактическое исчерпание квоты. Реальную квоту намеренно не исчерпывают. Ошибки соединения и таймауты сохраняют неизвестный usage без выдуманной стоимости.

Используется Google Chrome на Windows либо Playwright-managed Chromium (`pnpm exec playwright install chromium`). Путь задаётся через `CQA_BROWSER_EXECUTABLE`.

Опциональная проверка чистой установки: задайте `CQA_PNPM_SCRIPT` абсолютным путём к локальному `pnpm.mjs`, затем выполните `node node_modules/tsx/dist/cli.mjs scripts/verify-clean-setup.ts`. Она копирует публичные исходники в `tmp/`, ставит lockfile-зависимости из локального кеша офлайн, исключает ключи из окружения дочернего процесса, проверяет сборку и пустой сервер на 3019. Локальный кеш обязателен для этой офлайн-проверки; доступ к npm на другой машине ею не проверяется.

Независимая человеческая проверка остаётся незавершённым этапом; технические прогоны не доказывают точность продукта. Через 23 часа после официального старта открывается контрольный набор, через 24 — стоп-код. Абсолютное время старта не предоставлено; календарный дедлайн не выдумывается.
